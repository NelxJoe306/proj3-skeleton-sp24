# ADR-0003: runtime world 零随机

sp24 spec 的存档规则要求「读档后连 RNG 状态一起还原」，而 3B 起会有一个在结构之上变化的 **runtime world**（avatar 位置，未来还有机关、时刻）。一个看似自然的选择是：玩的过程中也用 RNG（随机刷怪、随机事件），然后把 RNG 内部状态存进快照。我们决定反过来：**运行时完全不消费 RNG**——一切随机性在 seed 生成期就固化进 structure layer，`getWorldFromInput` 的每一次调用都由 seed 重建结构再套快照，play 期间的每一步都是纯确定函数。取舍：牺牲「玩的过程中引入随机」的自由，换取 spec 的 RNG 还原要求被**平凡满足**（没有运行时可变的 RNG 状态可丢）、同 seed + 同按键序列 ⇒ 同结果永远成立（这是 ADR-0002 硬性不变式对 3B 的自然延伸），以及存档快照极简（只需 avatar 坐标这类显式值，无需存随机源状态）。未来若某个机制确实需要 play 期随机，需回到本 ADR 复议（那将要求快照携带并还原该 RNG 的状态）。
