# ADR-0004: stateless replay server（web 后端不持会话）

3C 要把 runtime world 接到浏览器。一个看似自然的选择是**有状态会话**：服务端按 session 持一个 `RuntimeWorld`，每键 `step(char)`，快但需要 session map、超时、并把"游戏在哪一步"的权威交给服务端内存。我们决定反过来：**服务端完全不持有会话**——每次请求都由一条「会话串」（size+seed+已按按键，或 读档+已按按键）纯函数式重建世界、重放按键、返回当前快照；浏览器持有会话串、每按一键**全量重放**一次。取舍：牺牲「省流量 / 服务端保留中间态」，换来**引擎仍是唯一真相源**（web 只是继 autograder 字符串、StdDraw 之后的又一个输入来源，输入来源无关），无 session 表可腐坏、无状态漂移，且浏览器端行为与本地 headless 测试吃**同一套重放语义**、永不分叉。80×80～120×120 的重建成本微不足道。未来若换回有状态，也只需在服务端加一层缓存，不改变引擎与文法。注：因此"赢后冻结""goal 位置"都必须能写成会话串的纯函数（见 ADR-0003/0005），这是本决策对引擎语义的硬约束。
